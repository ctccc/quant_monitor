# A 股量化短线盯盘工作站（Quant Monitor）—— 任务拆解与路线图

> 状态：规划稿 v1（2026-07）
> 配套文档：[技术架构](ARCHITECTURE.md) · [数据源方案](DATA_SOURCES.md)

---

## 1. 一句话定位

一个跑在自己电脑上的、服务于 A 股超短线/动能交易的个人盯盘工作站：
**盘前给简报、盘中报异动、盘后做复盘**，全部数据来自免费公开接口，零付费、零权限依赖。

## 2. 上一版为什么做不下去（复盘）

| 卡点 | 根因 | 本版对策 |
|------|------|----------|
| 数据接口不稳定 | 直接在业务代码里调 akshare，akshare 升级/网站改版就全挂 | 所有数据访问收敛到独立的**数据接入层**，业务代码不碰任何具体接口；接口挂了只改一处（见 ARCHITECTURE.md §3） |
| 数据权限 | 用了 tushare pro 等需要积分/付费的源 | **彻底放弃**一切需要注册积分、付费的数据源；只用东财/腾讯/新浪的免费公开接口，能力边界提前写清楚（见 DATA_SOURCES.md §5） |
| 可视化 / UI | 前端工具链（框架、打包）对单人项目太重 | 不引入任何前端框架和 Node 工具链：FastAPI 直接吐 HTML + ECharts（CDN 单文件），整个前端就是几个静态文件 |
| 一次想做完所有功能 | 盘中实时是最难的部分，却最先做 | 里程碑倒序难度：**先做盘后复盘**（数据静态、好调试、当天就能用上），再盘前，最后攻盘中实时 |

已有代码的处置：`monitor.py`（新闻关键词过滤）逻辑保留，未来迁移为盘前模块 F2.1 的一部分。

## 3. 功能需求拆解

按交易日的时间轴分为四大块。编号规则：P = 优先级块，F = 功能项。

### P0 · 基础设施（一切的地基）

| 编号 | 功能 | 说明 |
|------|------|------|
| F0.1 | 数据接入层 | 统一封装东财/腾讯/新浪接口：限速、重试、主备降级、字段标准化。业务层只见统一模型，不见 URL |
| F0.2 | 交易日历与调度器 | 知道今天是不是交易日、现在是盘前/盘中/盘后，按时段自动启停各采集任务 |
| F0.3 | 存储层 | SQLite 存结构化数据（涨停池、资金流、情绪指标、警报记录），Parquet 存行情快照历史 |
| F0.4 | Web 服务骨架 | FastAPI + WebSocket 推送 + 极简黑底看板框架，后续每个模块往里加页面 |
| F0.5 | 数据源体检脚本 | `scripts/check_datasources.py`，随时验证所有依赖接口的连通性和字段（已交付，见 §6 第一步） |

### P1 · 盘后复盘（15:00 之后）—— 最先做

| 编号 | 功能 | 说明 |
|------|------|------|
| F1.1 | 市场情绪面板 | 涨跌家数、涨停/跌停家数、炸板率、连板高度、两市成交额，及各指标的近 N 日走势。这是判断"明天能不能干"的核心仪表 |
| F1.2 | 涨停复盘 | 当日涨停池明细（首次封板时间、封单额、连板数、开板次数），按板块聚类；连板梯队图（1板→2板→…→最高板） |
| F1.3 | 板块资金流转 | 行业/概念板块当日主力净流入排行 + 近 5 日流向趋势，识别资金从哪来、到哪去 |
| F1.4 | 个股动向 | 自选股当日表现汇总；龙虎榜数据（游资席位动向） |
| F1.5 | 复盘笔记 | 每日一篇 Markdown 笔记（明日主线预判、计划），本地文件存储，看板内可读写 |

**情绪指标口径（先定义清楚，避免后面扯皮）：**
- 炸板率 = 炸板家数 ÷ (涨停家数 + 炸板家数)
- 连板高度 = 当日最高连板数
- 涨停家数：剔除 ST 与新股上市首日（可配置）

### P2 · 盘前简报（8:30 – 9:25）

| 编号 | 功能 | 说明 |
|------|------|------|
| F2.1 | 隔夜消息聚合 | 财经新闻按关键词过滤高亮（迁移现有 monitor.py 逻辑），重点公告提取 |
| F2.2 | 昨日涨停股跟踪 | 昨涨停/连板股名单，作为今日竞价观察对象 |
| F2.3 | 集合竞价监控 | 9:15–9:25 轮询：竞价高开率、昨涨停股竞价表现（核心情绪先行指标）、竞价异常放量个股 |
| F2.4 | 外围概览 | 隔夜美股三大指数、A50 期货、汇率快照 |
| F2.5 | 今日作战简报 | 把 F2.1–F2.4 聚合成一页"战斗简报"：情绪定性 + 主线候选 + 观察名单 |

### P3 · 盘中监控（9:30 – 15:00）—— 最难，最后攻

| 编号 | 功能 | 说明 |
|------|------|------|
| F3.1 | 实时行情引擎 | 全市场 5000+ 只股票快照轮询（3–5 秒/轮，约 10 个分页请求搞定，**不逐股请求**），内存中维护最新盘口 |
| F3.2 | 板块热度榜 | 板块实时涨幅 × 实时主力净流入双排序，开盘 5–10 分钟锁定"今日资金主攻方向" |
| F3.3 | 异动警报引擎 | 规则可配置，触发即在看板置顶 + 声音提示。默认规则见下表 |
| F3.4 | 涨停/炸板池实时 | 实时涨停池、炸板池、打板成功率，盘中情绪温度计 |
| F3.5 | 自选股盯盘面板 | 自选股实时价格/涨速/量比一览，异动单独高亮 |

**默认异动规则（v1，全部可在配置文件调参）：**

| 规则名 | 触发条件（示例默认值） |
|--------|------------------------|
| 爆量拉升 | 3 分钟涨幅 ≥ 2% 且 量比 ≥ 3 |
| 快速换手 | 5 分钟换手率 ≥ 1.5%（流通盘口径） |
| 触板 | 距涨停价 ≤ 0.5% |
| 炸板 | 从涨停价回落 ≥ 1% |
| 板块异动 | 板块指数 5 分钟涨幅 ≥ 1% 且板内涨停数增加 |

### P4 · 增强（做完前三块再说）

| 编号 | 功能 |
|------|------|
| F4.1 | 盘面回放：用存下来的快照历史"重放"任意一天，复盘自己的临盘决策 |
| F4.2 | 交易日志：记录自己的实际买卖，与系统信号对照统计 |
| F4.3 | 常驻服务化：开机自启、异常自动重启、日志轮转 |

## 4. 里程碑路线图

估时按"业余时间 + AI 辅助开发"给出，单位为自然周。

| 里程碑 | 内容 | 完成标志（验收标准） | 预估 |
|--------|------|----------------------|------|
| **M0 地基** | F0.1–F0.5 | 本地跑通体检脚本全绿；`uvicorn` 一条命令启动空看板；SQLite 里存进第一批涨停池数据 | 1 周 |
| **M1 盘后复盘** | F1.1–F1.5 | 任意交易日 15:30 运行，5 分钟内生成完整复盘页：情绪面板 + 涨停梯队 + 板块资金流 | 2 周 |
| **M2 盘前简报** | F2.1–F2.5 | 交易日 9:26 前自动产出"作战简报"一页 | 1–2 周 |
| **M3 盘中监控** | F3.1–F3.5 | 盘中连续运行 4 小时不崩；异动警报延迟 ≤ 10 秒；开盘 10 分钟内板块热度榜可用 | 2–3 周 |
| **M4 打磨** | P4 择需 | — | 持续 |

依赖关系：M0 → M1 → M2 → M3（严格串行，每一步都产出当天就能用的东西）。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 免费接口字段/地址变更 | 采集失败 | 适配层隔离 + 体检脚本快速定位 + 同类数据至少两个备源 |
| 请求频率触发反爬 | IP 被限 | 全市场快照走分页批量接口（每轮约 10 个请求），全局限速器兜底；绝不逐股轮询 |
| 免费 Level-1 快照只有 3 秒粒度 | 做不了逐笔/盘口深度分析 | 明确为能力边界：超短盯盘 3 秒足够；不做需要 Level-2 的功能（见 DATA_SOURCES.md §5） |
| 单人项目烂尾 | — | 每个里程碑独立可用；先复盘后实时，第 3 周起每天真实使用，用起来才有动力迭代 |

**免责声明**：本项目仅为个人研究与学习工具，所有数据来自公开渠道，不构成任何投资建议。超短线交易风险极高，决策责任自负。

## 6. 现在就开始：第一步

1. 在**你自己的电脑**上（沙箱网络不通行情接口）：
   ```bash
   pip install -r requirements.txt
   python scripts/check_datasources.py
   ```
2. 把输出结果反馈回来（哪些接口 ✅ 哪些 ❌）。
3. 根据体检结果微调数据源优先级，随即开工 M0。
