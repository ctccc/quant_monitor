# 技术架构与选型

> 配套文档：[任务拆解与路线图](PLAN.md) · [数据源方案](DATA_SOURCES.md)

## 1. 总体原则

面向"单人业余开发、长期自用"的现实，所有选型遵守三条铁律：

1. **越少的运行部件越好**——一个 Python 进程 + 一个 SQLite 文件就是全部，没有消息队列、没有独立数据库服务、没有前端构建步骤。
2. **业务代码永远不直接碰外部接口**——所有 HTTP 请求收敛在 `datasource/` 一层，接口挂了只改一处。
3. **每一层都可以单独跑起来调试**——采集器可以脱离 Web 跑，Web 可以用假数据跑。

## 3. 数据接入层（本项目成败的关键）

上一版死在这里，所以这层要重点设计。

### 3.1 结构

```
quant_monitor/datasource/
├── base.py        # 抽象接口 + 统一数据模型（Quote、SectorFlow、ZtPoolItem…）
├── eastmoney.py   # 东财 push2 系列（主力源：快照/板块/资金流/涨停池）
├── tencent.py     # 腾讯 qt.gtimg.cn（快照备用源）
├── sina.py        # 新浪 hq.sinajs.cn（快照备用源 2）
├── aksource.py    # akshare 封装（仅低频数据：历史K线、新闻、龙虎榜）
├── throttle.py    # 全局限速器（令牌桶，按 host 限频）
└── router.py      # 路由与降级：主源失败 N 次自动切备源，恢复后切回
```

### 3.2 关键设计决策

| 决策 | 理由 |
|------|------|
| 高频数据（盘中 3–5 秒轮询）**直连东财 HTTP 接口**，不经过 akshare | akshare 只是这些接口的爬虫封装，版本升级经常改函数名/返回列名；直连消除中间层，且可控制字段、分页、超时 |
| 低频数据（历史 K 线、新闻、龙虎榜）用 akshare | 一天调几次，稳定性要求低，开发省事；坏了影响的只是非核心功能 |
| 每类数据定义 dataclass 统一模型，适配器负责把各源字段翻译成统一模型 | 换源/加源不动业务代码；字段改名只改对应适配器 |
| 全局令牌桶限速（东财默认 ≤ 5 req/s，可配） | 防止触发反爬；所有请求共享一个预算 |
| 失败策略：单请求重试 2 次 → 标记源不健康 → router 切备源 → 体检脚本可手动诊断 | 盘中不能因为一个源抖动就黑屏 |

### 3.3 全市场快照的正确姿势

**不要逐股请求。** 东财 `clist` 接口一页可返回 100–200 只股票的完整快照（价格、涨幅、量比、换手、涨速、主力净流入），全市场 5000+ 只 = 每轮约 10 个请求，3–5 秒一轮完全在安全频率内。这一个接口就同时喂饱 F3.1/F3.2/F3.5 三个功能。接口细节见 DATA_SOURCES.md §2.1。

## 4. 技术栈清单

| 层 | 选型 | 为什么是它（而不是别的） |
|----|------|--------------------------|
| 语言 | Python 3.11+ | 数据生态 + 你已有基础 |
| HTTP 客户端 | httpx | 同时支持同步/异步，盘中轮询用异步并发分页 |
| 数据处理 | pandas | 标配 |
| Web 框架 | FastAPI + uvicorn | 自带 WebSocket、自动文档；单进程内跑调度器足够 |
| 调度 | APScheduler | 进程内定时任务，配合交易日历控制启停；不需要 cron/Airflow |
| 存储 | SQLite（结构化）+ Parquet（快照历史） | 零运维单文件；Parquet 按天分文件存盘中快照，供 F4.1 回放。**明确不用** PostgreSQL/ClickHouse——运维成本对单人项目是毒药 |
| 前端 | 原生 HTML/JS + ECharts 5（CDN） | 你上次卡在 UI：方案是**根本不搞前端工程**。每个页面 = 1 个 HTML 文件，ECharts 中文文档齐全，K线/热力图/梯队图全有现成配置。黑底极简风，无动效无装饰 |
| 盘中刷新 | WebSocket 推送（盘中页）+ 定时 fetch（盘后页） | 盘后页面没必要上 WS |
| 配置 | 单个 `config.yaml` | 关键词、自选股、警报阈值、限速参数全在一处 |
| 通知 | 看板置顶 + 浏览器 Notification + 本地声音 | 不接微信/钉钉推送（webhook 依赖外部服务，P4 再说） |

## 5. 项目目录规划

```
quant_monitor/
├── quant_monitor/           # 主包
│   ├── datasource/          # 数据接入层（见 §3.1）
│   ├── core/                # 纯业务逻辑：情绪计算、板块聚合、警报规则
│   ├── store/               # SQLite + Parquet 读写
│   ├── jobs/                # 调度任务：盘前简报、盘中轮询、盘后归档
│   ├── web/                 # FastAPI 路由 + static/ 下的 HTML 页面
│   └── config.py            # 配置加载
├── scripts/
│   └── check_datasources.py # 数据源体检（已交付）
├── data/                    # SQLite 文件 + parquet/（gitignore）
├── notes/                   # 复盘笔记 markdown（gitignore 可选）
├── config.yaml
├── requirements.txt
└── monitor.py               # 旧版新闻过滤，M2 时迁入 jobs/
```

## 6. 运行形态

- 开发/日常：`uvicorn quant_monitor.web.app:app` 一条命令，调度器随应用启动。
- 交易日自动化（P4）：注册为系统服务或计划任务，8:20 自动拉起。
- 所有时间判断基于交易日历（akshare 提供，M0 时落一份到 SQLite 供离线使用）。
